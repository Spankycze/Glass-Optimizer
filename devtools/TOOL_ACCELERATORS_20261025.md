## Nové akcelerátory vývoje – 25. 10. 2026

**Co je skutečně nasazené**
- `node-install-fast.ps1` nyní upřednostní Bun pouze v kanonickém kořeni tohoto projektu s ověřeným package name a `package-lock.json`. Bun používá `--no-save --no-progress --ignore-scripts`, ověřuje SHA-256 původního npm lockfilu a zakazuje nový `bun.lock`; při chybě Bunu neprohlašuje instalaci za úspěšnou a nepokračuje tichým npm retry. Jiné adresáře, explicitní `-ForceNpm` nebo chybějící Bun používají npm. `-PlanOnly` jen vypíše rozhodnutí bez instalace.
- Skutečná instalace v kořeni projektu: Bun PASS, lockfile nezměněn, `npm run graphics:test` PASS. V předchozím srovnatelném izolovaném měření zde Bun pro vývojové závislosti již vyšel rychlejší než npm; nevyměňovat ostatní správce balíčků bez testů.
- `devtools/watch-fast.ps1` využívá **watchexec 2.7** a je spouštěn **automaticky po úspěšném `build-fast.ps1`** přes `devtools/ensure-auto-watch.ps1`. Žádná ruční aktivace ani npm watch příkaz není potřeba. Každý projekt má právě jednu instanci; 1200ms debounce slučuje uložení, fronta neukončuje probíhající kontrolu. Kontroly se omezují na relevantní existující testy a během plného release buildu se přeskočí. Opakovaný totožný úspěšně ověřený obsah se přes SHA-256 přeskočí přibližně za 55–73 ms; otisky se kontrolují i po skončení testu. Při chybě/chybějícím zdroji nevzniká úspěšná cache.
- **sccache 0.18** již existuje ve stávajících RAM Guard nativních build skriptech. Na skutečném `third_party/yyjson/yyjson.c` opakovaný přímý MSVC compile ~12,9 s proti sccache hit ~0,126 s. Statistiky potvrdily 3/3 cache hits. Funkční smoke oba výsledné programy shodně ověřil jako `YYJSON_PARITY_17`. Jde pouze o zrychlení *opakované nezměněné kompilace*, nikoliv o zrychlení runtime nebo celého release.
- **hyperfine 2.0** byl použit k nezávislému měření, ale `bun run graphics:test` není v tomto Windows workflow kompatibilní s cestou `devtools\\run-js.cmd` (Bun shell z ní vytvořil nesprávný příkaz). Standardní npm runner zůstává. **fd 10.5** měl shodné výsledky jako .NET enumerace 2191/2191 v RAM Guardu, ale byl pomalejší (medián 51,1 vs 28,6 ms). Nezapínat fd plošně.
- Ninja zde bez souboru `build.ninja` nemá práci; uv a rg už jsou součástí existujících pomocných skriptů. Žádné nové vývojové závislosti ani globální změny Windows nejsou potřeba.

**Hranice:** Bez změn vydaných aplikací, instalací aplikací, prohlížečových profilů, uživatelských nastavení, síťových adaptérů, služeb nebo registrů. Nejde o CPU/RAM/FPS runtime benchmark.

Nemění instalovanou aplikaci ani její procesy. Ověřeně nainstalovaná verze zůstává 16.206, rozpracovaný zdroj 16.207.
